# UI 设计规范

GoKeep 面向重复操作的后台管理场景，界面应紧凑、清楚、稳定，优先支持扫描、筛选与批量操作。

## 基础规则

- 使用现有主题 token 与 Tailwind 配置，页面不得另建一套配色系统。
- 侧栏、顶栏和内容区保持统一尺寸；页面标题使用页面级字号，面板标题使用紧凑字号。
- 按钮按主操作、次操作、危险操作区分；危险操作执行前必须确认目标与影响。
- 表单标签、错误信息和必填状态清晰；提交过程中禁用重复操作。
- 表格默认支持加载、空状态、分页和窄屏横向滚动。
- 弹窗用于短表单和确认，长内容使用更宽的弹窗或独立页面。
- 卡片圆角不超过 8px，不使用无信息价值的装饰卡片或多层嵌套卡片。
- 浅色与暗色主题都必须保证文字、边框和状态色对比度。

## 可访问性

- 所有输入控件都有标签，纯图标按钮有 `aria-label` 或 tooltip。
- 键盘焦点清晰，弹窗可用 Escape 关闭并正确管理焦点。
- 文本不得覆盖相邻内容；长标识符和错误信息应换行、截断或滚动。

## 验收视口

- 桌面：`1920x1080`、`1440x900`、`1024x768`。
- 手机：`390x844`、`375x812`。
- 各视口不得出现不可控横向溢出、按钮文字裁切或交互元素重叠。
