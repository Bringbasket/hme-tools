# UI 设计规范

GoKeep 是长期、重复使用的管理系统，不是营销落地页。界面采用参考管理台验证过的“固定平台外壳 + 单一主区域 + 高密度数据操作”模式：安静、清楚、稳定，优先帮助用户扫描状态、筛选数据和完成批量操作。

## 产品视觉

- 页面以信息层级和操作路径为主，不使用超大标题、渐变背景、装饰光斑或无决策价值的指标卡。
- 一个页面只保留一个视觉主区域。区块使用背景、边框和留白建立层级，不把整页拆成多层悬浮卡片。
- 中文标题直接描述任务，不在标题上方重复放置无意义的英文眉题。
- 品牌色只用于主操作、当前选中项和少量关键数据；成功使用绿色，警告使用琥珀色，错误使用红色，处理中使用中性色或品牌色。
- 浅色和深色主题都必须保证正文、辅助文字、边框和禁用状态有足够对比度。阴影只用于弹窗、下拉菜单和确实浮于页面之上的控件。

## 平台外壳

- 桌面端侧栏宽度固定为约 `240px`，支持收起为图标栏；窄屏侧栏改为抽屉，打开时显示遮罩并可通过菜单按钮、遮罩或导航项关闭。
- 顶栏高度约 `80px`，只放移动菜单、当前页面标题和全局用户/主题操作；顶栏不放业务账号切换器或创建浮层。
- 主区直接使用平台 `.page` 容器，顶部为页面标题栏，底部和侧边界由平台统一控制。页面内容多少不得改变外层容器宽度。
- 平台必须为纵向滚动条预留稳定空间，状态切换、滚动条出现或消失不得造成水平位移。

## 页面骨架

业务页面按需使用以下结构，保持从上到下的信息顺序：

1. 页面标题栏：中文标题、简短说明和一个页面级主要操作。
2. 状态摘要：展示 2 至 4 项会影响当前决策的信息，优先紧凑横条，不默认使用独立卡片。
3. 标签页或分段控件：组织同一业务的子功能和视图。
4. 工具栏：搜索、筛选、每页条数、刷新和批量操作在同一水平区域内组织。
5. 主数据区：列表优先使用表格；无法压缩时切换为结构化移动列表或局部横向滚动。
6. 分页栏：展示当前记录范围、总数、每页条数、当前页和总页数。

同一操作只能有一个主要入口；不要同时放在标题栏、工具栏和表格行中。设置表单可以分节，但不在卡片中嵌套卡片。

## 尺寸与组件

- 页面区块间距使用 `24px`，控件组间距使用 `12px`，紧密元素使用 `6px` 或 `8px`。
- 页面标题建议 `20px-24px`，面板标题 `14px-16px`，正文 `13px-14px`，辅助信息不小于 `11px`。字号不随视口缩放，字间距为 `0`。
- 卡片和弹窗圆角最大 `8px`，按钮和输入框约 `6px`；图标按钮至少 `32px × 32px`，常规按钮高度 `34px-38px`。
- 固定格式的按钮、表格列、工具栏和分页栏必须有稳定尺寸；加载图标、状态文本和计数变化不能造成布局跳动。
- 统一使用 `.btn-primary`、`.btn-secondary`、`.btn-danger`、`.input`、`.badge-*`、`.data-table` 等主题组件类。新增类必须写入主题层并说明语义。

## 控件和交互

- 命令型操作使用“图标 + 文字”；刷新、关闭、展开、分页等熟悉工具操作使用 Lucide 图标按钮并提供 `title` 和 `aria-label`。
- 布尔设置使用开关或复选框；少量互斥模式使用分段控件；多个选项使用下拉菜单；数值使用数字输入框、步进器或滑块。
- 危险操作使用独立危险样式，执行前明确目标和后果；删除等高风险操作应要求输入完整目标名称确认。
- 短创建、编辑和确认使用标准弹窗；长文本、邮件和日志使用宽弹窗、抽屉或独立页面。弹窗标题直接描述任务，操作区固定在底部，取消在左、主要操作在右。
- 标准弹窗必须支持 Escape 关闭、Tab 焦点锁定、打开后首焦点和关闭后焦点恢复；业务页面不得重复手写遮罩和焦点逻辑。

## 数据表格和分页

- 列顺序按“身份信息 → 业务信息 → 状态 → 时间 → 操作”；主要标识允许两行展示，长文本单行截断并提供详情或 Tooltip。
- 表头、工具栏和分页栏在加载时保持可见；加载、空数据和错误使用不同状态，错误不能伪装成空数据。
- 超过一屏的列表必须提供每页条数，默认 `10`，常用选项 `10 / 20 / 50 / 100`。搜索、筛选和每页条数变化后回到第一页。
- 分页必须显示当前范围、总数、当前页和总页数；上一页、下一页在边界禁用，并提供可访问名称。
- 批量选择只针对当前已加载数据，准确显示选中数量；分页或筛选后清理不再有效的选择。

## 状态与反馈

每个异步区域至少覆盖以下状态，并保持区域尺寸稳定：

| 状态 | 表现 |
| --- | --- |
| 加载 | 显示加载图标和明确的进行中文案，保留表头及操作区 |
| 空数据 | 说明为空原因，只给一个最相关的下一步操作 |
| 错误 | 显示可理解的错误和重试入口，保留已有数据时不要清空数据 |
| 无权限 | 说明缺少权限，不显示误导性的空数据 |
| 禁用/提交中 | 仅禁用相关控件，保持原有尺寸 |
| 成功 | 显示真实结果；短提示由 ToastHost 自动消失 |
| 长文本 | 换行、截断或局部滚动，不遮挡相邻内容 |

全局短反馈统一使用 `showToast` 和 `ToastHost`；需要用户处理的错误必须留在触发操作附近持续显示。状态不能只依赖颜色表达。

## 响应式与无障碍

- 验收视口：`1440×900`、`1024×768`、`390×844` 和最窄 `320px`。
- 页面不得出现非预期横向滚动。表格无法压缩时使用明确的局部横向滚动容器，操作列不得覆盖数据列。
- 所有交互元素可通过键盘访问并保留清楚的焦点样式；图标按钮有可访问名称；最长标识符和错误信息必须能换行或截断。
- 动画只用于状态过渡和数值变化，遵守 `prefers-reduced-motion`。

## 页面交付检查

提交前逐项检查：标准页面骨架、重复标题和操作、加载/空/错/禁用/成功/长文本状态、浅色/深色主题、四种视口、控制台错误、横向溢出、滚动条稳定性、焦点管理和分页回归测试。前端目录执行 `pnpm typecheck`、`pnpm test:run` 和 `pnpm build`。
