# 部署与运维规范

## 本地依赖

`deploy/compose/docker-compose.yml` 仅启动 PostgreSQL、Redis 和 MinIO。复制示例配置后启动：

```powershell
Copy-Item .env.example .env
docker compose -f deploy/compose/docker-compose.yml up -d
```

示例密码只用于本机开发，不能用于公开环境。

## 构建

```powershell
pnpm install --frozen-lockfile
pnpm build
Set-Location server
go test ./...
go build -tags embed -o bin/gokeep-server ./cmd/server
```

生产环境以低权限用户运行二进制，通过反向代理终止 TLS，并只暴露必要端口。运行配置由环境变量注入。

## 发布检查

- 使用强随机 `JWT_SECRET` 和独立数据库凭据。
- 检查数据库、Redis 和可选 S3 的网络访问范围。
- 启动后检查 `/healthz`、`/readyz`、登录和系统管理页面。
- 发布前创建数据库备份并验证文件可下载。
- 保留上一版本二进制和回滚步骤，数据库变更必须有恢复方案。

## 监控与备份

- 日志输出到 stdout，由运行平台统一采集和轮转。
- 定时探测健康接口，关注 HTTP 5xx、登录失败和依赖连接错误。
- 备份文件保存到独立 S3 存储，设置保留策略并定期执行恢复演练。
- 数据库恢复会覆盖当前数据，只能由授权管理员在确认环境后执行。
