# 部署与运维规范

## 本地依赖

`deploy/compose/docker-compose.yml` 仅启动 PostgreSQL、Redis 和 MinIO。复制示例配置后启动：

```powershell
Copy-Item .env.example .env
docker compose -f deploy/compose/docker-compose.yml up -d
```

示例密码只用于本机开发，不能用于公开环境。

## 构建

```powershell
pnpm install --frozen-lockfile
pnpm build
Set-Location server
go test ./...
go build -tags embed -o bin/gokeep-server ./cmd/server
```

生产环境以低权限用户运行二进制，通过反向代理终止 TLS，并只暴露必要端口。运行配置由环境变量注入。

## 容器发布与在线更新

仓库根目录的 `Dockerfile` 会构建内嵌前端的单一 GoKeep 镜像；`release.yml` 在 `main` 或 `master`
提交后发布 `ghcr.io/bringbasket/gokeep:latest` 和提交 SHA 标签，并写入 OCI 版本与提交标识。

生产主机使用 `compose.server.yml`。首次部署前复制 `deploy/host/.env.example` 为根目录 `.env`，将
`GOKEEP_POSTGRES_PASSWORD`、`GOKEEP_REDIS_PASSWORD` 和 `JWT_SECRET` 替换为彼此不同的随机强值，再创建
可由容器 UID `10001` 读写的数据目录：

```bash
mkdir -p data/system data/mail
chown -R 10001:10001 data
chmod 700 data data/system data/mail
docker compose --env-file .env -f compose.server.yml up -d
```

在线更新需要 Docker、Docker Compose、Python 3 和 `flock`。默认安装目录是
`/www/wwwroot/gokeep`；其他目录需在 systemd 服务环境中设置 `GOKEEP_APP_DIR`，并同步修改
`gokeep-update.path` 的两个请求文件路径。安装更新执行器和文件监听器：

```bash
install -m 0755 deploy/host/gokeep-update /usr/local/sbin/gokeep-update
install -m 0644 deploy/systemd/gokeep-update.service /etc/systemd/system/gokeep-update.service
install -m 0644 deploy/systemd/gokeep-update.path /etc/systemd/system/gokeep-update.path
systemctl daemon-reload
systemctl enable --now gokeep-update.path
```

管理员在侧栏底部的“版本与更新”中先检查更新，再点击“立即更新”。应用仅写入 `0600` 请求文件；
宿主机任务拉取官方镜像，等待健康检查，失败时将应用服务回滚至上一镜像。任务状态同样以原子方式
写入 `data/system/update-status.json`，并归属 UID `10001`、权限 `0600`，不会暴露密码、令牌或邮件内容。

若需要手动回滚，先确认此前的镜像 ID：

```bash
docker image ls ghcr.io/bringbasket/gokeep
docker tag <previous-image-id> ghcr.io/bringbasket/gokeep:latest
docker compose --env-file .env -f compose.server.yml up -d --no-build --force-recreate --no-deps app
```

## 发布检查

- 使用强随机 `JWT_SECRET` 和独立数据库凭据。
- 检查数据库、Redis 和可选 S3 的网络访问范围。
- 启动后检查 `/healthz`、`/readyz`、登录和系统管理页面。
- 发布前创建数据库备份并验证文件可下载。
- 保留上一版本二进制和回滚步骤，数据库变更必须有恢复方案。

## 监控与备份

- 日志输出到 stdout，由运行平台统一采集和轮转。
- 定时探测健康接口，关注 HTTP 5xx、登录失败和依赖连接错误。
- 备份文件保存到独立 S3 存储，设置保留策略并定期执行恢复演练。
- 数据库恢复会覆盖当前数据，只能由授权管理员在确认环境后执行。
