# 后端开发规范

后端位于 `server`，使用 Go 1.25、Gin、Ent、PostgreSQL 与 Redis。

## 分层

- `cmd/server`：加载配置、连接依赖、启动与优雅退出。
- `internal/api`：路由装配、健康检查和 Web UI。
- `internal/<domain>/handler.go`：参数绑定、状态码和响应。
- `internal/<domain>/service.go`：领域规则、事务和数据访问。
- `internal/common`：认证授权、审计、限流和通用响应。
- `internal/ent/schema`：数据库模型的唯一来源。

## 编码规则

- 所有 I/O 接收并传递 `context.Context`，外部调用设置超时。
- 错误在边界处记录一次，日志使用 `log/slog` 结构化字段。
- 不记录密码、令牌、连接串、邮件授权码和对象存储密钥。
- Handler 不直接拼装复杂查询；Service 不依赖 Gin 上下文。
- 权限由后端强制检查，前端隐藏按钮不能替代授权。
- 后台协程必须由可取消 context 管理，并在服务关闭时退出。

## 数据模型

修改 `internal/ent/schema` 后执行：

```powershell
Set-Location server
go generate ./internal/ent
go test ./...
```

生成代码必须与 schema 一并提交，不手工修改生成文件。

## 测试

- 纯逻辑使用单元测试；Handler 使用 `httptest` 验证状态码和响应。
- 权限、事务、恢复和删除等高风险路径需要覆盖失败场景。
- 提交前运行 `go test ./...` 与 `go vet ./...`。
