# 移动端适配规范

GoKeep 以桌面端管理操作为主要体验，移动端至少保证登录、导航、系统管理和高频业务页面可查看并完成主要操作。移动端使用同一套 Vue 组件和数据流，通过响应式断点改变布局，不复制第二套页面。

## 断点与外壳

- `lg`（约 `1024px`）以上：侧栏固定显示，默认宽度约 `240px`，可收起为图标栏；顶栏固定在内容区顶部。
- 低于 `1024px`：侧栏变为抽屉模式，宽度保持可用触控范围；打开时显示遮罩，点击遮罩、菜单按钮或导航项关闭。
- 顶栏在窄屏保留菜单按钮、页面标题和必要的用户操作；标题过长时截断，不挤压菜单按钮。
- 页面主区使用稳定的水平内边距和纵向滚动；不得因为侧栏开关、滚动条或异步状态变化产生页面级水平位移。
- 页面区块在窄屏改为单列，状态摘要和工具栏允许换行；主要操作保持在标题栏或工具栏的稳定位置。

## 列表与数据

- 表格外层使用明确的局部横向滚动容器，并保留最小列宽；操作列始终可达，不覆盖数据列。
- 当表格在目标屏幕上无法保持可读性时，可切换为结构化列表或按行展开详情，但身份、业务信息、状态、时间和操作的顺序必须与桌面端一致。
- 搜索、筛选和每页条数控件允许换行；分页栏必须同时显示记录范围、总数、当前页和总页数，不能只保留两个无上下文箭头。
- 批量选择必须清楚显示已选数量；触屏操作只作用于当前加载数据。

## 表单、弹窗与反馈

- 表单在窄屏改为单列，标签保持可见；输入框和同组按钮使用明确网格或纵向布局，避免依靠文字高度对齐。
- 打开软键盘后，当前输入框、校验错误和提交按钮仍应可见；长错误信息必须换行。
- 弹窗宽度为视口减去安全边距，正文独立滚动，标题和底部操作始终可见；长内容使用宽弹窗、抽屉或独立页面。
- 弹窗沿用标准 `Modal.vue` 或 `AppDialog.vue`，保留 Escape 关闭、Tab 焦点管理、打开首焦点和关闭后焦点恢复。
- Toast 宽度不超过视口，成功提示自动消失，错误提示持续显示在对应操作区；不得用遮挡主要内容的全屏提示代替错误处理。

## 触控与可访问性

- 可点击区域建议不小于 `44px`，图标按钮至少 `32px × 32px`，并保留 `aria-label` 或可见文字。
- 所有交互元素可通过键盘访问，焦点样式清楚；状态不能只通过颜色表达。
- 不使用 hover 才可发现的关键操作；行操作在移动端改为明确菜单或详情入口。
- 动效遵守 `prefers-reduced-motion`，不通过缩放、位移改变控件的可点击边界。

## 验收矩阵

在 `390×844`、`375×812` 和最窄 `320px` 下至少检查：

- 登录、打开/关闭侧栏和页面切换；
- 列表加载、空数据、错误、筛选、每页条数、首尾页分页；
- 表单校验、提交中、成功和失败；
- 普通弹窗、长内容弹窗和软键盘遮挡；
- 最长标题、邮箱地址、错误信息和无数据说明。

验收结果必须确认无页面级横向滚动、元素重叠、文字裁切、侧栏宽度跳动和焦点丢失。
