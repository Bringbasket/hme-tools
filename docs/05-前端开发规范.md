# 前端开发规范

GoKeep 前端位于 `apps/web`，使用 Vue 3、TypeScript、Vite、Pinia、Vue Router、Tailwind CSS、Radix Vue 和 Lucide。本文档规定管理台页面的实现方式；在当前工作区中还需遵守工作区级 `docs/UI_GUIDELINES.md`，GoKeep 独立检出时以本目录的 UI 规范为准。

## 目录职责

```text
src/api/                 HTTP 客户端、领域请求和 DTO
src/components/          跨领域可复用组件
src/components/ui/       分页、弹窗、行操作等基础交互
src/layout/              侧栏、顶栏和内容区
src/router/              静态路由、动态路由和权限守卫
src/stores/              登录态、权限和跨页面业务状态
src/styles/              Tailwind 入口、主题 token 和基础组件类
src/views/<domain>/      按功能域组织的页面与局部组件
```

页面、请求和状态按同一领域放置。例如邮件领域使用 `views/mail`、`api/mail.ts` 和必要的 `stores/mail.ts`；跨领域能力才进入顶层目录。

## 页面与路由

- Vue 组件统一使用 `<script setup lang="ts">`，props、emits、请求参数和响应必须有明确类型。
- 登录页是独立全屏路由。路由守卫确认会话和权限后，才挂载 `layout/index.vue`、侧栏和业务页面。
- 新增页面必须同步后端动态菜单、前端路由组件、权限字符和页面标题；页面标题只保留一个中文主标题。
- 同一领域的子功能优先使用标签页或分段控件，避免为了视图切换增加一级菜单。
- 一级业务页面直接使用平台提供的 `.page` 容器，不得覆盖其宽度、最大宽度、水平 margin 或侧栏偏移。

## 请求与认证

- 所有业务请求统一使用 `src/api/http.ts` 导出的 Axios 实例和领域 API 函数；页面不得创建新的 Axios 实例，也不得散落手写 base URL。
- 请求层统一处理 `/api/v1` 前缀、超时、Bearer Token 注入和 401 跳转；页面只处理业务参数、成功结果和可操作的错误。
- 使用 `unwrap<T>` 解包统一响应时，保留明确的 DTO 类型；文件下载、导出等非 JSON 请求必须在领域 API 中单独声明响应类型。
- 不在前端日志、错误上报或状态展示中输出 Cookie、密码、API Key、Session 和真实邮件正文。错误消息应去除服务端内部堆栈和连接信息。

## 状态管理

- Pinia 只保存跨路由共享的状态，例如用户、权限、菜单、主题和移动侧栏；页面局部筛选、弹窗和加载状态保留在页面组件内。
- 异步请求至少区分 `loading`、`success`、`empty`、`error`、`forbidden` 和 `submitting`。不得用空数组掩盖失败，也不得在请求开始前显示成功消息。
- 列表优先复用 `AsyncState`；全局短反馈统一调用 `showToast` 并由 `ToastHost` 呈现。需要用户处理的错误必须留在对应操作区持续显示。
- 按钮进入提交中状态时保持原有宽高，只替换图标或文字；无关按钮不能同时显示加载状态。

## 页面组成约定

业务页面按需由以下区域组成，顺序保持一致：

1. `page-heading`：中文标题、简短业务说明和页面级主要操作。
2. 状态摘要：只展示影响当前决策的 2 至 4 项信息，优先紧凑横条。
3. 标签页或分段控件：组织同一领域的子视图。
4. 工具栏：搜索、筛选、每页条数和批量操作放在同一操作区。
5. 主数据区：列表优先使用表格，移动端可切换为结构化列表。
6. 分页：使用 `components/ui/Pagination.vue`，显示范围、总数、每页条数和页码。

页面只能有一个视觉主区域；设置表单可以分节，但不在卡片中继续嵌套卡片。

## 通用组件与样式

- 优先复用 `theme.css` 中的 `.btn-primary`、`.btn-secondary`、`.btn-danger`、`.input`、`.badge-*`、`.data-table` 和 `.card-glass`。业务页不得复制一份同名组件类或改变其语义。
- 命令型按钮使用图标加文字；刷新、关闭、展开、上一页和下一页等熟悉工具操作使用 Lucide 图标按钮，并提供 `title` 与 `aria-label`。
- 布尔设置使用开关或复选框，互斥模式使用分段控件，多个选项使用下拉菜单；不要用两个文字按钮模拟开关。
- 短表单、编辑和确认使用 `Modal.vue` 或 `AppDialog.vue`；长内容使用宽弹窗、抽屉或独立页面。不得在页面内重复实现遮罩和焦点管理。
- 表格外层必须是明确的局部滚动容器；表头、工具栏和分页栏不随数据加载状态消失。

## 列表、筛选与分页

- 列顺序按“身份信息 → 业务信息 → 状态 → 时间 → 操作”；长文本单行截断，通过详情或 Tooltip 查看完整值。
- 超过一屏的数据必须提供每页条数，默认 `10`，选项为 `10 / 20 / 50 / 100`。
- 分页显示当前记录范围、总数和“第几页 / 共几页”；搜索、筛选或每页条数变化后回到第一页。
- 批量选择只作用于当前已加载数据，界面准确显示已选数量；分页切换和筛选后清理无效选择。
- 空态说明为空的原因，并只提供一个最相关的下一步操作；失败态提供重试入口，不伪装成空态。

## 可访问性与稳定性

- 输入控件始终有可见标签；错误信息靠近字段，服务端错误靠近触发它的操作区。
- 所有交互元素可通过键盘访问，焦点样式清晰；弹窗支持 Escape、Tab 焦点锁定、打开首焦点和关闭后焦点恢复。
- 为纵向滚动条预留稳定空间；加载、空态和长文本不能让按钮、列宽、工具栏或分页栏跳动。
- 文字必须可换行或截断，不得覆盖按钮、状态和相邻内容；禁止页面级非预期横向溢出。
- 动效只用于状态过渡和数值变化，并遵守 `prefers-reduced-motion`。

## 检查命令

在 GoKeep 根目录执行：

```powershell
pnpm typecheck
pnpm lint
pnpm test
pnpm build
```

提交前还要按 `docs/06-UI设计规范.md` 和 `docs/08-移动端适配规范.md` 完成视口、主题和状态验收。
