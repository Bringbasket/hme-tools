# 总体架构与目录规范

GoKeep 采用前后端分离开发、生产环境可合并为单个 Go 二进制的管理台架构。前端平台外壳、业务页面和 API 领域边界必须保持稳定，避免功能增长后形成页面内自定义的第二套架构。

## 系统结构

```text
Browser
  |-- development --> Vite :5173 -- /api proxy --> Gin :8080
  `-- production  --> Gin :8080 (embedded Web UI + API)
                                      |-- PostgreSQL
                                      |-- Redis
                                      `-- S3-compatible storage (optional)
```

## 前端平台外壳

```text
App
  |-- /login                         独立登录流程，不挂载管理台外壳
  `-- AuthenticatedLayout
       |-- Sidebar                   桌面固定约 240px，窄屏抽屉
       |-- Header                    高度约 80px，页面标题和全局操作
       `-- Main > .page              业务页面唯一主内容区
            |-- page heading
            |-- status summary (optional)
            |-- view tabs / segmented control (optional)
            |-- filter and action toolbar
            |-- data region
            `-- pagination (when list is paged)
```

侧栏、顶栏和主区由 `apps/web/src/layout` 统一控制。业务页面不得改变平台外壳的宽度、左右边界或顶栏偏移；需要限宽时只限于弹窗、抽屉、表单字段和正文阅读区等内部组件。

## 目录

```text
apps/web/
  src/api/                HTTP 客户端、领域 API 与 DTO
  src/components/         跨领域可复用组件
  src/components/ui/      按钮、分页、弹窗等基础交互
  src/layout/             侧栏、顶栏和内容区
  src/router/             静态路由与动态路由装配
  src/stores/             跨页面状态、登录态和权限
  src/styles/             主题 token 与基础组件类
  src/views/<domain>/     按功能域组织的页面和局部组件
server/
  cmd/server/             服务入口、配置和生命周期
  internal/api/            路由装配、健康检查和静态资源
  internal/<domain>/       领域 Handler、Service 和 DTO
  internal/auth/           登录、会话和权限
  internal/common/         中间件、统一响应、审计和通用工具
  internal/db/             数据库连接与迁移
  internal/ent/            schema 与生成代码
  internal/redisx/         Redis 连接和键空间
  internal/system/         系统管理接口
deploy/compose/            本地 PostgreSQL、Redis、MinIO
scripts/                   开发、构建和链路验证脚本
docs/                      工程规范和 API 文档
```

## 领域边界

- Handler 负责参数绑定、认证授权、状态码和统一响应；Service 负责业务规则、事务和数据访问；前端页面不得绕过 API 直接访问数据库或缓存。
- 新增 hme-tools 功能时，先确定领域名称和数据归属，再分别创建 `server/internal/<domain>`、`apps/web/src/views/<domain>` 和 `apps/web/src/api/<domain>.ts`。只有确实跨页面共享的状态才进入 Pinia。
- 菜单由后端动态路由返回。新增页面必须同时定义菜单节点、前端路由组件、权限字符和默认标题；没有权限的页面不能只依赖前端隐藏按钮来保护。
- 同一业务的子功能使用页面内标签页或分段控件组织；只有数据上下文、权限或操作目标明显不同，才新增一级菜单。
- 平台顶栏只保留全局操作（移动菜单、当前用户、主题等），账号、租户或工作空间等业务上下文必须放在所属领域的账号管理页面。

## 请求与状态流

浏览器请求统一经过 `src/api/http.ts`，由其处理 base URL、认证头、超时和 401 跳转。页面负责把请求状态映射为加载、空数据、失败、无权限、提交中和成功等可见状态；短反馈统一由 `ToastHost` 呈现，需要处理的错误留在对应操作区。
